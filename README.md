# Roll Buddy

Roll Buddy is a face-recognition attendance system. It enrolls students, detects faces in class photos, matches those faces against a MongoDB-backed roster, and reports present, unrecognized, and not-seen students.

## Project Structure

```text
roll-buddy-main/
+-- backend/
|   |-- app.py             # Flask API and DeepFace recognition pipeline
|   |-- requirements.txt   # Python dependencies
|   `-- index.html         # Browser frontend
+-- app/
|   |-- www/index.html     # Frontend bundled into the Android app
|   |-- package.json       # Capacitor scripts and dependencies
|   |-- capacitor.config.json
|   `-- android/           # Native Android project generated by Capacitor
+-- .gitignore
`-- README.md
```

The backend and Android wrapper are separate parts of the same application. The backend must be running before the browser frontend or Android app can enroll or recognize students.

## Prerequisites

- Python 3.10 or newer
- MongoDB running locally, or a reachable MongoDB deployment
- Node.js and npm for the Android wrapper
- Android Studio and an emulator or physical device for Android builds

## Run the Backend

From `backend/`, create and activate a virtual environment, then install dependencies:

```powershell
python -m venv env
.\env\Scripts\Activate.ps1
pip install -r requirements.txt
```

Create `backend/.env` when the defaults do not apply:

```env
MONGO_URI=mongodb://localhost:27017
MONGO_DB=attendance-sys
FRONTEND_ORIGIN=*
```

Start the API:

```powershell
python app.py
```

The service listens on `http://localhost:5001`. DeepFace may download or warm its model on the first startup, and MongoDB must be available for roster operations.

## Use the Browser Frontend

Open `backend/index.html` in a browser after starting the backend. The UI supports student enrollment, bulk face detection, attendance recognition, roster listing, and student deletion.

The main API routes are:

| Method | Route | Purpose |
| --- | --- | --- |
| GET | `/health` | Check service health |
| GET | `/students` | List enrolled students |
| DELETE | `/students/<prn_gr>` | Delete a student |
| POST | `/detect_faces` | Detect and crop faces |
| POST | `/enroll` | Enroll or update a student |
| POST | `/recognize` | Recognize faces in a class photo |

## Build the Android App

From `app/`, install dependencies and sync the web assets into Capacitor:

```powershell
npm install
npx cap sync android
npx cap open android
```

Before syncing, set `API_BASE` in `app/www/index.html` for the device being used:

- Browser on the same computer: `http://localhost:5001`
- Android emulator: `http://10.0.2.2:5001`
- Physical phone on the same network: `http://<computer-lan-ip>:5001`

After changing `app/www/index.html`, run `npx cap sync android` again. Build the APK from Android Studio using **Build > Build Bundle(s) / APK(s) > Build APK(s)**.

## Configuration

The backend reads these environment variables:

| Variable | Default | Description |
| --- | --- | --- |
| `MONGO_URI` | empty | MongoDB connection string; configure this in `.env` |
| `MONGO_DB` | empty | MongoDB database name; configure this in `.env` |
| `FRONTEND_ORIGIN` | `*` | Allowed browser frontend origin |

Student PRN/GR numbers are the unique roster key. Embeddings remain on the backend and are not returned by the student-list endpoint.
